## 1. 启动与基本操作

### 1.1 使用 EXE

1. 打开项目的 `releases` 目录。
2. 双击 `MetaAWD-Desktop-20261119-162436.exe`。
3. 看到左侧「工作台、服务器管理、站点防御、站点攻击、平台工具」分组，即为新版。
4. 如果窗口加载失败，确认系统为 Windows x64，并已安装 Microsoft Edge WebView2 Runtime。

EXE 已包含 Python 和前端资源，不需要为了运行 EXE 再安装 Node.js、Go 或 Python。PWN 流量转发导出的 C 程序需要另外在 Linux 编译，这与运行 Windows EXE 是两回事。

请把 EXE 放在当前用户可写的目录。运行数据保存在 EXE 同级的 `tmp` 下；例如从 `releases` 启动时，数据位于 `releases/tmp`。

`MetaAWD-v3.5.exe` 等旧文件是 Tkinter 版，不包含本文所有页面。

### 1.2 使用源码

已经安装源码依赖时，双击 [tool/start.bat](../tool/start.bat)。首次安装命令见 [项目首页](../README.md)。

源码模式下的运行数据通常位于 `tool/tmp`。直接在浏览器打开 HTML 只能查看界面，不能代替桌面窗口执行 SSH、文件选择或导出操作。

### 1.3 常用界面行为

| 操作 | 说明 |
| --- | --- |
| 左上角侧栏按钮 | 展开或折叠导航；窄窗口下打开抽屉导航 |
| 侧栏底部主题按钮 | 默认浅色，可切换深色 |
| 顶部空白区域 | 在支持自定义窗口按钮的 Windows 窗口中拖动窗口 |
| 页面中的「浏览」 | 选择本机文件或目录，不是浏览服务器目录 |
| 页面中的服务器路径 | 手动填写 Linux 路径，例如 `/var/www/html` |
| 按钮显示“处理中”或变灰 | 可能正在执行任务，也可能未满足 SSH、输入或结果条件 |
| 切换页面 | 当前会话中已访问页面通常保留表单状态 |
| 关闭后重新打开 | 不应假设所有表单、扫描结果、连接和后台任务会自动恢复 |

有些文件、扫描、备份任务共享一个后台作业槽。前一项没结束时，其他按钮会暂时禁用。SSH 终端和 Bugku 提交有各自的会话状态。

## 2. 第一次使用的推荐顺序

### Web 站点防御路线

1. **SSH 连接**：测试成功，确认当前主机和帐号。
2. **源码备份**：先下载一份站点原始备份。
3. **WebShell 查杀**：先关闭自动删除，查看扫描结果和报告。
4. **WAF 管理**：配置站点、安装目录和日志目录，再确认部署。
5. **请求审查**：同步日志，核对正常请求是否被误处理。
6. **文件监控**：为已经确认的站点建立基线。
7. 根据需要开启 **WAF 守护** 和 **请求自动同步**。

### PWN 路线

1. 使用 **PWN 沙箱防护 → ELF 体检** 确认程序架构和基础加固项。
2. 需要限制系统调用时，选择 ELF 加固副本或 systemd 策略。
3. 需要记录交互、包装程序或转发 TCP 会话时，使用 **PWN 流量转发**。
4. 在 Windows 中生成预览、导出文件。
5. 在目标兼容的 Linux 环境编译或安装，并验证正常交互。
6. 保留原程序、策略、部署包和回滚材料。

**两个 PWN 页面都不会因为点击“导出”就自动改动服务器。** 当前版本的流量转发模块是构建与部署包生成器，不是在 Windows 上点击一次便持续监听端口的代理服务。

## 3. 防御概览

入口：**工作台 → 防御概览**。

用于查看当前会话的摘要：

- SSH 是否已验证，以及当前帐号和主机。
- 文件监控是否运行、暂停或停止。
- WAF 本次会话是否部署、守护是否运行。
- 已同步到本机的请求日志数量。
- 最近一次扫描的目标、总数、恶意数和可疑数。

「配置 SSH」「打开查杀」和常用操作可以直接跳转到相应页面。

“本次未部署”不代表服务器绝对没有 WAF。重新打开工作台后，会话状态会重新建立；服务器上之前写入的 WAF 文件仍可能存在。

<a id="ssh"></a>
## 4. SSH 连接

入口：**工作台 → SSH 连接**。

### 参数怎么填

| 参数 | 示例 | 说明 |
| --- | --- | --- |
| 主机地址 | `192.0.2.10` | IP 或主机名；不要填 `http://`、URL 路径 |
| 端口 | `22` | SSH 端口，不是网站端口或 PWN 服务端口；范围 1–65535 |
| 用户名 | `pwn` / `root` | 使用服务器实际提供的帐号 |
| 密码 | 服务器密码 | 使用本机 SSH 密钥认证时可留空；当前页面没有单独的私钥文件选择框 |

### 操作步骤

1. 填写连接参数。
2. 点击 **测试连接**。
3. 等待连接日志显示验证成功。
4. 核对右上角或侧栏底部显示的主机身份，再开始远端操作。

SSH 验证为交互终端、文件监控、远端查杀、WAF 和备份提供连接信息。某些操作会重新建立 SSH/SFTP 连接，所以“刚才能登录”不代表之后不会因网络或权限变化失败。

### 切换主机

先停止文件监控和 WAF 守护，再填写新主机并测试连接。切换后原终端会关闭，请求自动同步会停止，远端扫描结果不能直接用于新主机的文件处置。

<a id="terminal"></a>
## 5. SSH 交互终端

入口：**服务器管理 → SSH 交互终端**。

1. 先在 SSH 连接页验证服务器。
2. 点击 **打开终端**。
3. 在下方「终端输入」中输入一行，按 Enter 或点击 **发送**。
4. 在输出区域查看结果。
5. 长命令需要中断时点击 **Ctrl+C**；结束时点击 **断开会话**。

可以先用以下只读命令确认环境：

```sh
whoami
pwd
uname -m
```

这是按行输入的持久 PTY 会话，`cd` 等状态可在同一会话中保留；它不是完整终端模拟器，`vim`、全屏 TUI、方向键交互等不一定适合在这里使用。复杂编辑可在独立 SSH 客户端中完成。

关闭窗口、切换已验证 SSH 连接或断开会话会停止该终端。需要长期运行的 Linux 服务应交给服务器自己的服务管理器，而不是依赖工作台终端保持在线。

<a id="monitor"></a>
## 6. 文件监控

入口：**服务器管理 → 文件监控**。

### 用途

为服务器目录建立文件哈希基线，并在监控日志中记录新增和修改。当前新版监控入口用于观察变化，不会自动把所有变化当成恶意文件删除。

### 操作步骤

1. 验证 SSH。
2. 填写「服务器目录」，例如 `/var/www/html/`。
3. 点击 **开始监控**，等待状态变为运行中。
4. 查看下方「监控日志」。
5. 临时停看可点 **暂停**，之后点 **继续**。
6. 更换目录或服务器前，点击 **停止**，等待回到未启动状态。

应在确认站点当前内容后建立基线。监控前就已存在的异常文件不会因为“有基线”而变成正常文件；需要结合查杀和人工检查。正常上传、缓存和日志写入也可能触发变更记录。

<a id="backup"></a>
## 7. 源码备份与恢复

入口：**服务器管理 → 源码备份**。

### 7.1 下载备份

1. 验证 SSH。
2. 在「服务器路径」填写站点实际目录，例如 `/var/www/html/`。
3. 在「下载目录」选择 Windows 本机保存目录，例如 `D:\AWD\backups`。
4. 点击 **打包并下载**。
5. 等待备份日志显示完成，核对实际保存路径和压缩包。

建议在部署 WAF、注释代码或启用自动删除之前做一次备份。不要只凭按钮恢复可点击就判断成功，要看完成日志与本地文件。

### 7.2 从备份恢复

1. 核对当前 SSH 主机。
2. 核对「服务器路径」是否为要恢复的站点。
3. 选择本地 `.tar.gz` 或 `.tgz` 备份文件。
4. 点击 **恢复到站点**，阅读确认框后确认。
5. 等待恢复日志，随后访问网站，检查关键业务和文件权限。

恢复会替换目标站点文件，后端带备份与失败回滚处理。不要把失败回滚等同于界面上存在任意历史版本的一键撤销；重要原始备份仍应单独保留。

这个模块主要处理站点目录文件。数据库、外部存储、系统服务配置等不会因为备份网站目录就自动得到完整备份。

<a id="scanner"></a>
## 8. WebShell 查杀

入口：**站点防御 → WebShell 查杀**。

### 8.1 选择扫描范围

| 模式 | 输入 | 是否需要 SSH |
| --- | --- | --- |
| 本地扫描 | Windows 本机目录或文件；可点「浏览」「选择单个文件」 | 否 |
| SSH 远端扫描 | Linux 服务器目录 | 是 |

### 8.2 阈值怎么理解

当前默认恶意判定阈值为 **200**，以界面加载后的值为准：

- 分数达到阈值：判为 **恶意**。
- 分数达到阈值的 40%，但不到恶意阈值：判为 **可疑**。
- 以默认 200 为例，80–199 属于可疑，200 及以上属于恶意。

分数是规则命中的累计结果，不是“恶意概率百分比”。降低阈值会增加检出，也可能增加误报；提高阈值则相反。

### 8.3 推荐的第一次扫描

1. 选择本地或远端模式，填写目标。
2. 保持 **自动删除恶意文件** 关闭。
3. 点击 **开始扫描**。
4. 查看总文件数、恶意数、可疑数、文件路径、类型和分数。
5. 点击 **保存报告**，记录页面显示的保存位置。
6. 对可疑文件结合业务代码和实际用途复核。

### 8.4 注释危险代码

1. 完成扫描，确认有尚未处理的恶意文件。
2. 点击 **注释危险代码**，先生成注释计划。
3. 查看计划中的文件与行数。
4. 点击 **执行注释**，在确认框中确认。
5. 复查日志和业务功能。

只有当前扫描结果符合条件时才能操作。切换 SSH 主机或重新扫描会影响计划有效性。修改前会保留备份；并非所有代码都能自动生成可用的注释方案。

### 8.5 自动删除恶意文件

打开开关后，每次扫描开始都需要确认。程序对本次判为恶意的文件再复核，完整备份成功后才从原路径移除。

结果可能显示：

- **已备份并移除**：已完成文件处置。
- **跳过或未确认**：文件变化、备份失败或其他条件不满足，查日志。

备份和恢复清单位于 `tmp/scan-quarantine/` 对应批次中，页面会显示实际目录。这里的恢复材料不是站点 `.tar.gz`，不要直接拿它当「源码备份」页面的压缩包恢复。

<a id="waf"></a>
## 9. WAF 管理

入口：**站点防御 → WAF 管理**。

该模块为 PHP 站点部署内置 WAF，会写入 WAF 文件并为业务 PHP 文件添加引用。它不是系统级网络防火墙，也不负责所有非 PHP 请求。

### 9.1 部署参数

| 参数 | 默认值 / 示例 | 用途 |
| --- | --- | --- |
| 站点目录 | `/var/www/html/` | 需要处理的 PHP 站点目录 |
| 安装目录 | `/var/www/html/.phpwaf` | WAF 模板和相关文件所在位置 |
| 日志目录 | `/tmp/.phpwaf_logs` | 服务器保存 HTTP 采集日志的位置，PHP 运行帐号需要可写 |
| 拦截方式 | 关键词替换 / 跳转路由 | 命中时采用的处理方式 |
| 跳转路由 | `/` | 选择跳转路由模式时使用 |
| 严格程度 | 简单 / 常见 / 全量 | 控制启用的关键词规则范围；默认全量 |
| 记录全部请求 | 默认关闭 | 开启后也记录未命中的 PHP 请求 |

关键词替换会改变匹配到的请求内容，跳转路由会改变命中请求的响应流程。两种方式都应验证正常登录、查询、上传等业务。

### 9.2 首次部署

1. SSH 验证成功，并完成站点备份。
2. 核对站点、安装和日志目录。
3. 选择拦截方式、严格程度及是否记录全部请求。
4. 点击 **部署 WAF**，核对确认框中的主机与目录。
5. 查看 WAF 日志，等待部署完成。
6. 从浏览器访问正常页面和关键业务。
7. 到「请求审查」同步日志，核对采集和判定。

默认关闭“记录全部请求”时，没有规则命中就可能没有新的 HTTP 日志；这不一定表示 WAF 没加载。

### 9.3 守护、模板更新与卸载

| 按钮 | 行为 |
| --- | --- |
| 启动守护 | 本次已部署后可用；工作台运行期间约每 5 秒检查，忙于其他作业时跳过本轮 |
| 停止守护 | 停止后续检查；切换 SSH 前应停止 |
| 更新日志模板 | 先把远端原模板备份到本机，再写入新的采集模板；只影响后续采集 |
| 卸载 WAF | 按指定站点和安装路径移除 WAF 引用；查看日志确认结果 |

重新打开工具后，页面可能显示“本次未部署”。如果服务器实际已有 WAF，先填写其真实目录，必要时用 **更新日志模板**，不要因为会话标签就盲目重复注入。

参数锁定时，说明当前会话已部署或有任务执行。需要改变部署配置时先确认备份、停止守护，按卸载后重新部署的流程操作。

<a id="packets"></a>
## 10. 请求审查

入口：**站点防御 → 请求审查**。

用于查看 PHP WAF 的 HTTP 请求日志。PWN 的 `.log` 文件不在此页面显示。

### 10.1 手动同步

1. 验证 SSH。
2. 填写「远端日志目录」，必须与 WAF 配置一致。
3. 点击 **同步请求**。
4. 从左侧请求列表选择记录。
5. 在右侧查看 **原文、请求头、正文**。

同步先把文件完整保存到本机，随后尝试清理远端对应日志。因此同步后的服务器目录变空可能是正常现象。

### 10.2 自动同步

开启自动同步后，空闲时约每 **5 秒**检查；失败时约 **15 秒**重试。存在共享后台作业时会等待。

关闭开关时，已开始的单个文件下载会收尾；切换服务器或关闭工具会停止自动同步。

### 10.3 筛选与结果理解

- 搜索框：按方法、路径、对端 IP 等内容筛选。
- **全部结果**：显示全部本地记录。
- **规则命中**：筛选匹配、跳转或终止的记录。
- **未命中**：采集到但未触发规则的请求。
- **无判定信息**：常见于旧格式日志或元数据不完整。

顶部的新命中提示表示新同步到本机的命中，不是所有网络流量。点击“查看命中”可进入对应筛选。

### 10.4 导出、刷新与清空

| 操作 | 说明 |
| --- | --- |
| 刷新本地 | 重新读取磁盘上的日志，不等于从服务器下载 |
| 保存 HTTP 原文 | 保存完整采集字节，移除工具内部元数据前缀 |
| 清空本地请求日志 | 删除当前主机对应的本机日志，需要确认；不是清理远端所有日志 |

界面详情最多预览前 **64 KiB**。看到截断提示时导出完整原文查看。正文显示不可用不一定是空请求：某些 PHP multipart 场景本身无法提供原始正文。

<a id="pwn-sandbox"></a>
## 11. PWN 沙箱防护

入口：**站点防御 → PWN 沙箱防护**。

原来的“PWN 防护”已改为这个名字，包含 **ELF 体检、ELF 加固副本、systemd 策略** 三个页签。

### 11.1 ELF 体检

1. 在「ELF 文件路径」选择本机 ELF。
2. 点击 **开始体检**。
3. 查看架构、位数、字节序、SHA-256 和加固项。

| 结果 | 含义 |
| --- | --- |
| NX 栈 | 根据 GNU_STACK 段检查栈是否要求可执行 |
| PIE | 程序是否具有位置无关可执行文件特征 |
| RELRO | 检查只读重定位保护及立即绑定情况 |
| Canary | 是否发现相关栈保护失败处理符号 |
| FORTIFY | 是否发现相关受检库函数符号 |

体检是静态读取，不执行、不修改 ELF。符号被剥离或静态链接时，未发现符号不等于确定没有该保护；“未知”也不是“关闭”。

### 11.2 ELF 加固副本

支持 **Linux x86-64 可执行 ELF，包括 PIE**。输出是启动器和策略，并不把原 ELF 的机器码补丁改成另一套程序。

操作：

1. 选择「待加固 ELF」。
2. 选择沙箱预设，再按业务需要调整开关。
3. 点击 **预览**，查看将拦截的系统调用。
4. 点击 **生成加固副本**，选择本机导出目录。
5. 将成套文件放到 Linux 上服务帐号不可写的目录。

三个预设：

| 预设 | 主要限制 | 需重点测试 |
| --- | --- | --- |
| Sandbox 1 · 基础防护 | 挂载、内核管理、跨进程调试 | 常规启动和请求处理 |
| Sandbox 2 · 文件保护 | 基础防护，加文件句柄、删除和重命名 | 临时文件替换、缓存、日志轮转 |
| Sandbox 3 · 网络与派生限制 | 基础防护，加套接字建立和进程/线程创建 | 自行监听、数据库连接、线程池、子进程 |

Sandbox 2 和 3 是不同组合，不是“3 包含 2 的全部规则”。手动组还包括主动连接等选项，以预览中的实际系统调用清单为准。

导出文件：

```text
run-hardened   Linux 启动器
program.elf    原程序字节副本
policy.json   SHA-256 和规则配置
```

在包含这三个文件的 Linux 目录中运行：

```sh
chmod 755 run-hardened program.elf
./run-hardened
```

启动器先核对哈希，再设置 `no_new_privs` 和 seccomp。动态链接程序仍依赖服务器加载器与库；需要内核支持 seccomp BPF 且挂载 `/proc`。不要把文件留在服务帐号可修改的目录后就认为策略可信。

此方式保留了启动和动态加载所需调用，不等同于“禁止所有 execve”或“杜绝所有 PWN”。若正常功能失败，依据预览逐组调整并重新导出。

### 11.3 systemd 策略

适用于已由 systemd 管理的 Linux 服务。

| 参数 | 说明 |
| --- | --- |
| 服务单元 | 例如 `demo.service`，不是 ELF 文件路径 |
| 系统调用策略 | 沿用配置、限制高风险调用、常规服务白名单 |
| 文件系统 | 沿用配置、系统目录只读、严格只读 |
| 套接字地址族 | 沿用配置、仅 Unix、Unix/IPv4/IPv6 |
| 可写例外 | 每行一个绝对路径；严格只读服务需要列出业务落盘位置 |
| 隔离路径 | 每行一个绝对路径，阻止服务访问指定区域 |
| 禁止获取新权限 | 限制后续执行提升权限 |
| 隔离临时目录 | 独立 `/tmp` 和 `/var/tmp` |
| 仅允许原生 ABI | 限制兼容 ABI；32 位兼容服务需验证 |
| 限制可执行内存 | 可能影响 JIT 或可执行栈程序 |
| 限制临时目录执行 | 覆盖 `/tmp`、`/var/tmp`、`/dev/shm` |

操作：填写参数 → **生成策略预览** → 查看每条指令解释 → **导出 .conf**。

例如服务名为 `demo.service`，导出文件名为 `90-metaawd-pwn.conf`。在 Linux 中，先将该文件上传到当前目录，再执行：

```sh
sudo mkdir -p /etc/systemd/system/demo.service.d
sudo install -m 644 90-metaawd-pwn.conf /etc/systemd/system/demo.service.d/90-metaawd-pwn.conf
systemctl cat demo.service
sudo systemd-analyze verify demo.service
sudo systemctl daemon-reload
sudo systemctl restart demo.service
systemctl status demo.service --no-pager
```

把示例服务名换成实际单元。只对目标版本支持的指令应用配置；检查合并后的服务单元和业务结果。撤销时移除本次新增的 drop-in，或恢复原有同名文件，再 daemon-reload 和重启服务，不要删除该服务的其他配置。

<a id="pwn-forward"></a>
## 12. PWN 流量转发

入口：**站点防御 → PWN 流量转发**。

### 12.1 这个模块如何工作

```text
Windows 工作台：填写参数 → 生成构建预览 → 导出构建包
Linux 服务器：编译所选模式 → 核对服务配置 → 部署 → 实测交互
```

四种程序都以 **标准输入/输出**承接单次连接。对外监听端口由 xinetd 或其他服务管理方式提供。仅运行 `./forward` 不会自动创建 TCP 监听端口。

当前支持 Linux x86/x86-64、IPv4 TCP 目标。多目标输入不支持域名、IPv6 或 UDP。上游参考项目为 [i0gan/pwn_waf](https://github.com/i0gan/pwn_waf)，本工具在其思路上加入了参数校验、部署回滚和运行边界处理。

### 12.2 四种模式怎么选

| 模式 | 数据流 | 适用用途 |
| --- | --- | --- |
| CATCH | 客户端 → 原程序；记录标准 I/O | 保留原业务，观察交互 |
| I0GAN | 客户端 → 原程序；遇指定调用终止本次进程 | 在兼容性验证后增加调用阻断 |
| FORWARD | 客户端 → 一个固定 IPv4:端口 | 将入口会话代理到一个后端服务 |
| FORWARD_MULTI | 新连接依次选择 hosts.txt 目标 | 在多个目标之间轮询分配连接 |

**CATCH / I0GAN：** 原程序从「原程序备份路径」启动。备份由 root 管理，服务帐号可读、可执行但不可写。记录范围主要是标准文件描述符上的 `read` / `write`，不是整机抓包。

**I0GAN 的当前规则：** 初始 execve 后，在跟踪进程出现 `open`、`clone` 或 `execve` 时结束本次处理并记录 `AVOID`。这是固定调用规则，不是全面系统调用白名单；不涵盖所有等价接口或所有利用方式。正常程序如果依赖这些调用，也可能被终止。先在 CATCH 下验证原业务，再测试 I0GAN。

**FORWARD_MULTI：** 一条连接只选择一个目标，不会把同一份交互同时广播给所有目标。目标不可达会使该次会话失败；当前没有自动跳过故障目标的健康检查和重试切换。

### 12.3 运行与转发参数

| 参数 | 默认值 | 怎么填 |
| --- | --- | --- |
| 服务程序路径 | `/pwn` | Linux 当前服务可执行文件，部署时会替换它；必须是已存在的非符号链接普通文件 |
| 原程序备份路径 | `/opt/metaawd-backup/pwn.original` | 每个服务使用独立路径；也作为 CATCH/I0GAN 的执行目标 |
| 单目标 IPv4 | `127.0.0.1` | 从运行转发程序的 Linux 主机看过去的后端地址 |
| 目标端口 | `20000` | 后端实际监听端口，1–65535 |
| 多目标列表 | 两条回环示例 | 每行 `IPv4:端口`，忽略空行、`#` 注释和重复项，最多 256 个 |

Linux 路径请用不含空格、跳转段和控制字符的规范绝对路径。备份不能放到服务帐号可写的日志目录内。

多目标示例：

```text
# 两个独立的本地测试后端
127.0.0.1:20000
127.0.0.1:20001
```

`127.0.0.1` 指 Linux 代理所在主机，不是你运行 EXE 的 Windows 主机。若代理在容器内，回环也仅指该容器。

### 12.4 xinetd 参数

| 参数 | 默认值 | 范围与含义 |
| --- | --- | --- |
| 服务名 | `metaawd-pwn` | 配置名；对应 `/etc/xinetd.d/metaawd-pwn` |
| 监听 IPv4 | `0.0.0.0` | 所有 IPv4 网卡；只供本地测试可填 `127.0.0.1` |
| 监听端口 | `10000` | 对外入口端口，1–65535 |
| 服务用户 / 用户组 | `pwn` / `pwn` | 必须已存在；脚本不会自动创建帐号 |
| 单来源并发 | `10` | 1–1024，同一来源可同时运行的实例数 |
| 总实例上限 | `128` | 1–4096，服务总体并发上限 |
| CPU 秒数 | `20` | 1–3600，进程 CPU 时间限制，不是网络连接空闲超时 |
| 内存限制 MiB | `256` | 16–65536，xinetd 的进程地址空间限制 |
| 安装 xinetd 配置 | 开启 | 部署脚本写入对应配置，并保留旧配置记录 |
| 重新加载方式 | `systemctl` | 可选 `systemctl restart xinetd`、`service xinetd restart` 或仅写配置 |

生成的是独立 xinetd 配置，不会自动识别并停掉原有的 systemd/socat/xinetd 监听。部署前用 `ss -ltnp` 检查入口端口；同一端口不能让两个独立服务重复占用。

如果关闭「安装 xinetd 配置」，脚本仍会备份和替换服务程序，但不会新建监听服务。此时需由已有服务配置承接连接。

### 12.5 构建与日志参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 目标 x86 架构 | x86-64 | 32 位选择 x86，Makefile 添加 `-m32`；与原程序/目标运行环境匹配 |
| 编译器 | gcc | 可选 musl-gcc，需自行安装对应工具链 |
| 优化级别 | O2 | O0 便于调试，Os 偏向体积；通常保持 O2 |
| 静态链接 | 开启 | 编译包装程序时添加 `-static`，需要静态库；不会把原业务 ELF 的依赖自动静态化 |
| 移除符号 | 开启 | 添加 `-s`，减小产物；需要调试可关闭 |
| 额外编译警告 | 开启 | 添加 `-Wall -Wextra` |
| 运行数据目录 | `/tmp/.metaawd-pwn` | 保存交互日志、多目标 hosts.txt 与 `.multi_index` |
| 日志目录权限 | 0770 | 新建目录时使用；0750 为属主可写，0770 为用户组也可写，0777 为所有用户可写 |
| 记录流量日志 | 开启 | 开启时保留原始内容和十六进制表示；关闭后不产生交互日志 |

同一方向的十六进制缓存上限为 **1 MiB**，达到后出现 `hex log truncated at 1 MiB` 标记，原始字节继续写入文件。该限制不是磁盘总配额，长期运行仍需关注目录大小和磁盘空间。

已有日志目录仅检查属主和写权限，不会按下拉框重新 chmod。多目标即使关闭日志，也需要数据目录保存 hosts.txt 与轮询状态。

### 12.6 生成和导出

1. 选择模式并填好参数。
2. 点击 **生成构建预览**。
3. 查看模式、构建命令、目标数、Makefile、xinetd 配置与提示。
4. 点击 **导出构建包**，选择本机目录。
5. 记录页面返回的实际导出目录。

参数改变后旧预览会失效，需要重新生成。导出是在所选父目录下创建新的构建包子目录，不会自动上传服务器。

典型包内容：

```text
Makefile
src/waf.c
src/waf.h
src/logger.c
src/logger.h
LICENSE
xinetd-metaawd-pwn
deploy.sh
rollback.sh
README.txt
policy.json
hosts.txt              仅导出多目标模式时提供
```

Makefile 包含四个构建目标，但 **deploy.sh 固定部署你导出时选择的模式**。例如导出 CATCH 包后执行 `make forward`，不会让 deploy.sh 自动变成 FORWARD 部署脚本；换模式应回界面重新预览、导出。

`policy.json` 是配置清单，不是 C 程序每次启动读取的动态配置。改监听、目标、原程序路径等参数后，应重新导出和编译；hosts.txt 是多目标运行时文件，可在部署主机对应目录管理。

### 12.7 Linux 编译与部署示例

以下以 **CATCH**、服务 `/srv/pwn/challenge`、备份 `/opt/metaawd-backup/challenge.original`、用户/组 `pwn` 为例。先在界面填成这些值并导出，不能只复制命令却仍使用不匹配的配置。

#### 第一步：确认环境

在目标兼容的 Linux 构建环境中：

```sh
uname -m
file /srv/pwn/challenge
id pwn
getent group pwn
ss -ltnp
```

确认：

- 机器和原 ELF 架构匹配。
- 原程序实际能运行。
- `pwn` 用户、组存在。
- 入口端口无重复监听。
- 编译器、make 已安装。Debian/Ubuntu 示例：`sudo apt-get install build-essential`；使用自动生成的服务配置还需安装 xinetd。

32 位编译还需匹配的 multilib/32 位开发库；静态链接缺库时安装相应库，或回界面关闭静态链接重新导出。动态产物需要目标系统提供相容 glibc，建议在目标机或兼容的构建环境编译。

#### 第二步：上传并编译

使用 SFTP/SCP 或自己的文件传输工具，将整个构建包上传 Linux。进入**包含 Makefile 的目录**：

```sh
make catch
file catch
sh -n deploy.sh
sh -n rollback.sh
```

其他模式分别使用：

```sh
make i0gan
make forward
make forward_multi
```

`make all` 会生成四个包装程序。Windows EXE 不会替你在本机运行 Linux GCC。

#### 第三步：核对部署前提

```sh
sed -n '1,220p' deploy.sh
cat xinetd-metaawd-pwn
```

重点看服务路径、备份路径、监听端口、服务用户和是否重启 xinetd。

- 备份父目录必须 root 拥有，组和其他用户不可写，服务用户需要可进入。
- 若父目录不存在，脚本会按 root 与服务组创建；上层目录也应可信。
- 若数据目录已存在，应归服务用户所有且可写；不要填 `/tmp`、`/var/log` 这样的公共父目录当专用日志目录。
- 若服务在 chroot/container 内运行，路径必须从该进程实际可见的根目录计算。生成脚本不自动复现原 chroot 启动参数，不能直接覆盖旧配置后假设环境相同。

#### 第四步：部署和测试

保持在构建包目录内：

```sh
sudo sh deploy.sh
```

脚本会保存原程序和 `.meta` 元数据，并把备份设为 root 管理、服务组只读执行，再替换服务程序；开启安装配置时处理 xinetd 文件并按选择重新加载。

从另一个终端检查：

```sh
ss -ltnp
nc 127.0.0.1 10000
```

这里的 `10000` 换成你配置的入口端口；远程测试时把地址换成服务器实际 IP。使用业务正常输入完成一次完整交互，确认菜单、输入、输出和退出都正确。

CATCH/I0GAN 程序应能通过 stdin/stdout 交互。自行创建网络监听、依赖特殊工作目录、传参或 chroot 的程序，需要同步配置其启动环境；当前表单没有工作目录和任意 server_args 字段。

#### 第五步：查看日志

```sh
sudo ls -lt /tmp/.metaawd-pwn
sudo du -sh /tmp/.metaawd-pwn
```

选择具体 `.log` 文件读取。日志含二进制内容时用十六进制工具或文本编辑器查看，不要把终端显示异常直接当成文件损坏。

日志通常包含模式、时间、read/write 方向、原始字节、`r_0` / `w_0` 等十六进制表示。I0GAN 命中会记录 `AVOID`。PWN 日志不会被「请求审查」自动同步，需要自行用 SFTP 下载。

#### 第六步：回滚

在同一构建包目录中：

```sh
sudo sh rollback.sh
```

回滚恢复原程序字节及 UID/GID/权限；如果部署时管理了 xinetd，也恢复原配置，或在明确记录原配置不存在时移除本次配置。之后再次检查端口和业务。

保留备份文件及其 `.meta`、`.xinetd` / `.xinetd.absent` 相关记录。不要随意删掉其中一部分。重复部署会复用已有备份；如果原业务程序后来升级，旧备份不会自动变成新版本，应先恢复并归档旧部署材料，为新版本使用新的独立备份路径。

### 12.8 两个转发模式的最小配置思路

**单目标：** 后端已在 Linux 本机 `127.0.0.1:20000` 提供服务；设置入口 `10000`，模式 FORWARD，目标 `127.0.0.1:20000`。客户端连 `10000`，后端实际处理 `20000`。

**多目标：** 两个独立后端分别在 `127.0.0.1:20000` 和 `127.0.0.1:20001`；模式 FORWARD_MULTI，列表填两行。连续新建两条连接，分别核对落到不同后端。

避免将目标配置回代理自身。工具会检查明显的相同地址/端口和回环自环，但无法仅凭配置获知服务器所有网卡、NAT 或端口映射，仍需核对真实网络关系。

### 12.9 与沙箱防护一起使用

先单独验证每个模块，再组合。CATCH/I0GAN 自身需要 ptrace 和子进程；如果在它们外面套用禁止 ptrace、clone/fork 的沙箱规则，包装程序可能无法启动。FORWARD 需要创建套接字和 connect；禁止这些调用会使转发失败。

## 13. 系统日志

入口：**站点防御 → 系统日志**。

集中查看当前会话的 SSH、监控、扫描、WAF、请求同步、备份和攻击辅助事件。失败项会带失败标识。

该页面保留最近约 **160 条**事件，属于当前进程的操作记录，不是持久化的无限历史数据库。重要结果应保存报告、请求原文或截图；PWN 交互日志和 Bugku 提交结果要到各自位置查看。

排错时先看：操作的主机/路径是否正确 → 是否有任务尚未完成 → 最近失败消息，而不是连续重复点击同一个按钮。

## 14. 目标探活

入口：**站点攻击 → 目标探活**。

用于生成或读取后续「攻击辅助」使用的目标列表。这是本机发出的 HTTP 探测，不依赖 SSH 连接，也不是 ICMP ping 或通用端口扫描。

### 14.1 快速探活

| 参数 | 示例 | 说明 |
| --- | --- | --- |
| URL 模板 | `http://team-?.example.test/` | 必须包含 `?`，将被替换为编号 |
| 起始编号 | `1` | 包含起点 |
| 结束编号 | `10` | 包含终点；编号范围 0–65535，单次最多 4096 个目标 |
| 存活文件 | `D:\AWD\targets.txt` | 本机 UTF-8 输出文件，探活完成后覆盖写入 |

点击 **快速探活并写入**，等待日志和站点列表更新。模板中的 `?` 是编号占位符，不要把普通 URL 查询分隔符误当作保留字符。

未出现在结果中不等于机器关闭：DNS、HTTP 返回、认证、重定向或超时都可能影响结果。对已知地址可以人工核对后从文件读入。

### 14.2 直接载入列表

准备 UTF-8 TXT，每行一个站点 URL：

```text
# 本地测试站点
http://127.0.0.1:8080/
http://127.0.0.1:8081/
```

在「目标文件」选择该文件，点击 **从文件读入**。空行、`#` 注释和重复项会处理掉。列表刷新只重读当前列表，不会重新执行网络探活。

## 15. 攻击辅助

入口：**站点攻击 → 攻击辅助**。

用于比赛/测试环境中已有、已知接口的检测和批量操作。它使用「目标探活」载入的站点和你提供的接口参数，不会自动寻找漏洞，也不自动推断未知口令。

### 15.1 检测已知后门

先载入目标，再填写：

| 参数 | 含义 |
| --- | --- |
| 后门路径 | 相对站点的已知 PHP 路径，例如页面默认的 `public/img/1.php` |
| key 方式 | 无、GET 或 POST，按已有接口约定填写 |
| key 参数名 / key 值 | 对应已有接口的认证参数 |
| 命令方式 | GET 或 POST |
| 命令参数名 | 接口接收执行内容的字段名，例如 `cmd` |

点击 **检测已知后门**。找到结果后会出现编号和关联站点列表。

当前检测主要依据路径响应状态及是否返回整页 HTML 做筛选，结果是“疑似存在”，不代表已验证 key 正确、执行功能可用或拥有写权限。某个正常短响应页面也可能被识别为候选。

### 15.2 选择记录与执行

1. 在「后门记录」选择编号。
2. 核对 key、命令方式以及「本次操作的站点」。
3. 按接口类型填写执行内容：eval 类型接收 PHP 代码，system 类型接收系统命令。
4. 先用只读身份检查验证接口，例如 system 类型的 `id`；eval 类型对应 `system('id');`。
5. 点击 **执行命令**，从攻击辅助日志查看各站点响应。

操作会作用于**所选记录中的全部站点**，不是只作用于 SSH 页显示的那一台主机。重新加载存活目标也不一定会自动重建旧后门记录的站点集合，应明确核对当前记录。

### 15.3 生成新后门页面的参数

该区域通过所选已有接口写入随机 PHP 文件，不使用 SSH/SFTP 上传。

- **写入目录**：服务器文件系统中的绝对目录。
- **Web 访问目录**：该目录对应的 URL 路径；例如文件系统 `/var/www/html/public` 可能映射为 URL `/`，不能机械地照抄。
- **生成带 key 后门**：开启后随机生成 key、key 值和命令参数。
- **生成新后门并上传**：操作前确认；返回记录后核对站点范围、文件路径和日志结果。

生成操作对已有接口的执行语义和目录写权限有要求。检测通过不等于上传一定成功。新记录会写入 `tmp/attacker/attacker_shells.json`，其中含接口地址和认证信息，分享日志、备份或整个 `tmp` 目录前应检查内容。

## 16. Bugku 批量提交

入口：**平台工具 → Bugku 批量提交**。

将已经取得的 flag 提交给内置的 Bugku PVP 计分端。它不是自动采集器，也不是可任意配置地址的通用提交客户端。

### 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 队伍 Token | 空 | 填当前比赛有效 Token |
| Flag 列表 | 空 | 每行一条，空行跳过 |
| 导入 TXT | — | 选择本机 UTF-8 TXT，导入会替换当前列表 |
| 提交间隔 | 250 ms | 250–10000 ms，上一条结束后再等待此时间 |
| 请求超时 | 5 秒 | 1–60 秒，连接与读取分别使用此超时 |
| 单批上限 | 256 | 1–256，超过时先缩减列表 |
| 重复项处理 | 只提交首次出现 | 可改为发现重复项即校验失败 |

### 操作步骤

1. 粘贴 flag 或导入 TXT。
2. 调整间隔、超时、上限和重复策略。
3. 点击 **预览批次**，核对有效条数、空行和重复数；这一步不会提交。
4. 输入 Token，点击 **提交批次**。
5. 查看逐行结果；需要停止后续条目时点击停止按钮。
6. 批次结束后导出 CSV。

### 结果状态

| 状态 | 含义 |
| --- | --- |
| 已确认 | 平台返回已被识别为接受的响应 |
| 已提交过 | 平台表示重复提交 |
| 被拒绝 | 平台返回明确拒绝 |
| 待确认 | 超时、限流或响应无法明确识别；到平台核对，不要直接当失败重交 |
| 未发送 | 停止或其他原因导致未发出 |

点击停止时，已经发出的请求可能仍会完成。CSV 导出的是原输入行号、状态和说明，不包含原始 flag 和 Token；不要把 CSV 当作原始 flag 列表备份。

<a id="data"></a>
## 17. 数据存放位置与迁移

### 17.1 本机数据

| 数据 | EXE 模式下的位置 |
| --- | --- |
| HTTP 请求日志 | EXE 同级 `tmp/<主机>/waf_logs/` |
| 未连接主机的本地请求 | `tmp/default/waf_logs/` |
| WAF 更新前的模板备份 | 对应主机的 `waf_logs/templates/` |
| 默认查杀报告 | `tmp/<主机>/webshell_report_*.txt` |
| 自动移除的备份和恢复清单 | `tmp/scan-quarantine/` 中对应批次 |
| 攻击辅助后门记录 | `tmp/attacker/attacker_shells.json` |
| 目标探活结果 | 页面指定的存活文件；默认位于 `tmp/attacker/` |
| 站点压缩包、PWN 包、CSV | 用户选择或页面提示的导出位置 |

源码模式将上述运行数据根目录换成 `tool/tmp`。

同一主机名的不同 SSH 端口/帐号可能共用按主机名生成的 HTTP 日志目录，查看历史日志时要结合记录内容和连接信息判断。

### 17.2 更新 EXE

- 新旧 EXE 放在同一目录时，会使用同级 `tmp`；旧数据不会因为文件名增加时间戳就自动迁移到别处。
- 把 EXE 单独复制到其他目录后，原 `tmp` 不会自动跟随。需要保留历史数据时，关闭工具后一起备份相应目录。
- 不建议两个工作台进程同时操作同一份运行数据或同一服务器的写入任务。

### 17.3 Linux 上的数据

PWN 日志、备份、元数据和 xinetd 配置位于你在表单中指定的服务器路径。关闭 Windows 工作台不会自动撤销已经部署的 Linux 程序，也不会替你清理这些日志。

<a id="faq"></a>
## 18. 常见故障速查

| 现象 | 先检查什么 |
| --- | --- |
| 没有 PWN 流量转发入口 | 是否打开新版带时间戳的 Desktop EXE，而非旧版 Tkinter |
| 提示工作台运行服务未连接 | 是否直接在浏览器打开 HTML；改用 EXE 或 start.bat |
| 远端按钮一直灰色 | SSH 是否成功；是否还有共享后台任务未结束 |
| 切换 SSH 被阻止 | 先停止文件监控和 WAF 守护 |
| 终端打开后断开 | SSH 主机、认证、主机公钥是否变化；重新测试连接 |
| 文件监控不断报变化 | 目录是否包含正常缓存、上传或日志；结合业务判断 |
| 查杀发现很多可疑文件 | 检查阈值与文件实际用途；先保存报告，不直接开启删除 |
| WAF 部署后业务异常 | 从备份和日志确认引用、规则与目录；测试关键词替换/跳转是否影响业务 |
| 请求审查没有记录 | WAF 是否已加载、路径是否一致、日志目录是否可写、是否只记录命中 |
| 自动同步不刷新 | 是否有其他任务占用、当前主机是否改变、是否处于失败重试间隔 |
| 请求正文为空或截断 | 查看正文状态和截断提示；导出原文，核对 PHP 是否提供正文 |
| PWN 导出后 Windows 不能运行 catch | catch 是待在 Linux 编译/运行的包装程序；不是 Windows EXE |
| `gcc: command not found` | 在 Linux 安装编译器与 make |
| `-m32` 编译缺头文件或库 | 安装匹配的 32 位开发库，确认原 ELF 架构 |
| 静态链接缺 libc 等库 | 安装静态库，或关闭静态链接并重新导出 |
| `GLIBC_x.xx not found` | 构建环境比部署机新；在目标兼容环境重编译 |
| PWN 提示原程序不存在或无权限 | 原路径、备份、父目录可进入权限、运行帐号及 chroot 可见路径 |
| PWN 部署提示备份元数据缺失 | 不要只留 original 文件而删除 .meta；核对是否混用旧包/旧备份路径 |
| I0GAN 一运行就断 | 正常程序可能触发 open/clone/execve；先用 CATCH 核对流程 |
| FORWARD 连接失败 | 目标地址是从 Linux/容器视角计算的吗；后端端口是否监听 |
| FORWARD_MULTI 部分连接失败 | 检查列表中每个目标；当前没有故障自动跳过机制 |
| PWN 入口连接不到 | 是否启动 xinetd、配置是否加载、端口是否冲突、防火墙是否放行 |
| PWN 日志不在请求审查里 | HTTP 与 PWN 日志是独立格式，PWN 日志需自行下载 |
| 攻击辅助检测成功但无执行结果 | 检测只筛疑似路径；核对认证参数、接口类型与记录中的全部站点 |
| 新接口地址访问失败 | 文件系统写入目录与 Web 访问目录是否真正对应 |
| Bugku 显示待确认 | 到平台核对结果，再决定是否重试 |

排错时记录：当前版本、模块、主机、路径/端口、实际点击步骤、完整错误消息，以及是否能用独立 SSH/HTTP/TCP 客户端复现。不要在反馈中附带真实密码、Token 或完整接口凭据。
